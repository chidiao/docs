# 收藏

用户给出链接并收藏时，按此流程收录到 `/nav/`。

## 指令

用户明确说明类型时，直接按指令分类：

- **收藏网站** → 按「网站」流程归类。
- **收藏插件** → `nav/ide-plugin.md`。
- **收藏项目** → `nav/project.md`。

未标类型时先初步判断；仍模糊则询问用户。

## 分类

**注意：不以链接来源（如 GitHub / Gitee 仓库地址）判断类别。**

- **插件**：IDE / 编辑器插件（VSCode Marketplace 等）。
- **项目**：用于阅读、学习、作为参考的开源代码仓库。
- **网站**：其余站点（含仅为获取 Release / 下载软件而收藏的仓库）→ 归入现有类目：
  - 资源 → `nav/resource`（二级分类：资源站 / 游戏）
  - 软件 → `nav/software`（二级分类：系统装机 / 效率工具 / 文件与卸载 / 网络工具 / 影音壁纸）
  - 开发 → `nav/develop`（二级分类：运行时与工具 / 编辑器 / 数据库）
  - 前端资源 → `nav/frontend`（前端库、教程站、AI 建站等）

## 流程

1. 按上方确定类别。
2. **获取信息**：用 `webfetch` 访问链接，确认名称与用途，名称以站点/插件/仓库标题为准。
3. **追加条目**：按「[链接条目](/skills/link-entry/SKILL)」写入对应文件：`### 标题` + `[名称](地址)` + 简介。
4. **更新导航**：仅当新增类目时才改动 `nav/index.md`、`nav/sidebar.ts`。
5. **构建验证**：运行 `pnpm docs:build`。

## 约定

- 类型不确定时先问用户，不要盲目归类或新增类目。
- 标题用简短名称，链接名称可用正式称呼，简介一句话。
